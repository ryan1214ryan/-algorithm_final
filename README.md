# 🎮 Unity 2D 雙層混合層級導航系統 (Hybrid LOD Navigation System)

本專案實作於 **Unity 2022.3.7f1**，成功手寫結合了微觀 **A\* 尋路演算法** 與宏觀 **Dijkstra 全域流場 (Flow Field)** 技術，解決海量單位 (58+ 實體) 同時尋路時的 CPU 效能崩潰危機。

---

## 📂 核心演算法原始碼位置 (Core Architecture)

### 1. 微觀 A\* 尋路大腦 ➔ `Assets/Scripts/AStarPathfinding.cs`
*   **關鍵公式對齊 ($f = g + h$)：** 
    *   `gCost`：起點到當前的真實累積成本（第 1 節）。
    *   `hCost`：當前到玩家的預估代角線距離（呼叫 `GetDiagonalDistance()` 函式）。
    *   `fCost => gCost + hCost`：適應度排序依據。
*   **八向整數幾何成本：** 水平垂直直走一步 `Cost = 10`；斜對角走一步 `Cost = 14`（精確對齊 $\sqrt{2} \approx 1.414$ 的物理比例）。
*   **斜切防穿牆過濾：** 展開鄰居時，若為斜向移動，會額外檢查交叉兩側是否包含不可通行之黑牆（`isWall`），只要有一側是牆即強制淘汰（`continue`），徹底封死 2D 穿模 Bug。
*   **C# 容器選擇：** `openList` 採用標準 `List<Node>` 動態陣列。受惠於 5x5 警戒框，最大搜尋節點數 $M \le 49$。在小規模數據下，利用連續記憶體優勢，完美觸發 **CPU L1/L2 快取命中 (Cache Prefetching)**，平均能耗僅需 **0.2229 ms**。

### 2. 宏觀全域流場管理 ➔ `Assets/Scripts/FlowFieldManager.cs`
*   **全域 Dijkstra 積分場：** 以玩家為 $0$ 勢能核心向外擴散，遍歷 $47 \times 20$ 網格（總計 940 個有效節點）計算勢能梯度，生成指向低勢能的二維歸一化向量 `flowDirection`。
*   **非同步時間記憶緩衝區：** 流場固定每 12 幀才非同步重算一次，其餘 11 幀個體查表讀取記憶緩衝區，完美平攤 CPU 計算峰值。
*   **快取效能跳變實測：** 開局首次建構耗時 **39.0234 ms**（快取失效 Heap 配置）；後續動態跨框重算耗時暴跌至 **7.1124 ms**（100% 快取命中），降幅高達 **81.7%**。

### 3. 怪物 AI 狀態機與運動平滑 ➔ `Assets/Scripts/MonsterAI.cs`
*   **雙層層級狀態機 (LOD)：** 每幀判定自身與玩家的距離，踏入 5x5 警戒框切換為 $A^*$ 模式（局部追擊）；外圍大部隊則全面切換為流場模式（常數查表 $\mathcal{O}(1)$ 行動）。
*   **雙線性向量插值 (轉向平滑)：** 實作 `GetSmoothedFlowDirection()` 方法，個體移動時同時讀取周圍最近的 4 個網格向量並進行 `Vector3.Lerp` 三維權重融合，根除傳統網格過渡分水嶺時的 90 度機械式抖動，創造滑順的生物曲線軌跡。

## 🕹️ 簡易操作守則 (Quick Start Guide)

無論是在 Unity 編輯器中點擊 Play，或是直接執行匯出（Build）後的 `.exe` 執行檔，皆可透過以下鍵盤熱鍵進行即時互動與效能驗證：

### 1. 玩家移動控制
*   鍵盤 **`W` `A` `S` `D`**（或方向鍵）：控制中央的**綠色圓球**（玩家實體）在白色地板上自由行走。
*   **動態引導測試：** 當你操控玩家穿過狹窄走廊或繞過黑色外牆時，外圍的 58 隻紅色怪物大部隊會即時、滑順地動態調整追擊路線。

### 2. 核心技術與 Debug 可視化切換
*   按鍵 **`F` 鍵**：**全域流場向量箭頭開關**。按下後畫面上會亮起密密麻麻的「藍色動態向量箭頭」，即時渲染出整張地圖當前的 Dijkstra 勢能梯度方向。
*   按鍵 **`Tab` 鍵**：**混合層級狀態機 (LOD) 與純 A\* 尋路模式切換**。
    *   *LOD 模式（預設）：* 僅在玩家周圍 5x5 的綠框內啟動 $A^*$，維持 60 FPS 極致流暢度。
    *   *純 A\* 模式：* 強制全場 58 隻怪物無論距離多遠，每幀都獨立跑完整的 $A^*$ 搜尋。可用來向教授 Demo 傳統導航在沒有流場控管時造成的效能震盪與 FPS 掉幀。
*   按鍵 **`P` 鍵**：**硬體計時器能耗抓取鍵**。按下後系統會調用 `System.Diagnostics.Stopwatch`（工業級物理秒錶），即時抓取並更新當前的「10 幀滾動平均能耗」。左上角儀表板會跳動顯示最新的 $A^*$ 平均能耗（穩定於 0.22ms）與流場全域建構能耗（穩定於 7.11ms）。

### 3. 動態壓力測試與刷怪控制
*   按鍵 **`1` 鍵**：**生成單隻紅色怪物**。可在指定地點動態補怪，觀察單一隻怪物的近距離接戰與斜切防穿牆過濾行為。
*   按鍵 **`2` 鍵**：**一鍵大量刷怪 (壓力測試)**。可在地圖外圍瞬間生成大部隊，用來測試在 50+、100+ 隻暴增單位的極端情況下，流場的 $\mathcal{O}(1)$ 常數查表如何發揮效能神話、死死壓制 CPU 算力。
*   按鍵 **`3` 鍵**：**一鍵清除全場怪物**。清空畫面，方便重新進行單體或群體尋路軌跡的科學觀測。
*   按鍵 **`4` 鍵**：**怪物行為暫停/重啟開關**。按下後會將全場紅色怪物的物理移動定格（Freeze），但後台的尋路演算法與流場梯度依舊持續保持運算。適合用來靜態檢視、拍攝報告所需的 $A^*$ 黃色軌跡折線與藍色向量箭頭交織的可視化 Output 畫面。

### 4. $A^*$ 軌跡即時渲染說明
*   當任何紅色怪物踏入玩家周圍的 5x5 警戒框（綠框）時，其腳下會自動亮起一條**「發光黃色折線」**。這代表該單位已精確調用手寫 $A^*$，渲染出的折線即為該個體目前繞牆追擊的最短路徑。
